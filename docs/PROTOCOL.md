# zM1 通信协议

zM1 空气检测仪（斐讯悟空 M1）固件的通信约定。本工具所有收发都遵守这份协议；
`apps/server/src/device/zm1.ts` 是唯一的编解码实现，下行字段有白名单校验。

## 1. 通信通道

设备支持两种通道，报文体完全一致，只是承载方式不同：

| 通道 | 说明 |
| --- | --- |
| MQTT | 设备连到 broker 后收发；推荐，稳定 |
| UDP 广播 | 无 broker 时的局域网兜底；本机监听 `10181`，设备监听 `10182`，发往 `255.255.255.255` |

选择规则：设备配置了「总是通过 UDP 发送数据」，或服务端与 broker 断连时，走 UDP；否则走 MQTT。

## 2. MQTT 主题

`<mac>` 为设备 12 位小写十六进制地址。

| 方向 | 主题 |
| --- | --- |
| 控制下发 | `device/zm1/<mac>/set` |
| 状态回报 | `device/zm1/<mac>/state` |
| 传感器周期上报 | `device/zm1/<mac>/sensor` |
| 在线状态 | `device/zm1/<mac>/availability`（payload 非 JSON：`1` 在线，`0` 离线） |

服务端订阅 `device/zm1/+/state|sensor|availability`，发布使用 QoS 1。

## 3. 报文格式

JSON 对象，`mac` 为必填字段；设备只执行 `mac` 与自己一致的报文。

```json
{ "name": "zM1_1234", "mac": "aabbccddeeff" }
```

**查询语义**：把某个字段的值写成 `null`（不带引号），设备不改动该配置，只回报当前值。
本工具所有「读取配置」的操作都是这么实现的。

设备回包的字符串总长度有限（约 1023 字节），需要多组数据时应分多条查询。

## 4. 字段

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `mac` | string | 12 位小写十六进制设备地址，必填 |
| `name` | string | 设备名称 |
| `PM25` | 数字 | PM2.5，单位 μg/m³ |
| `formaldehyde` | 数字 | 甲醛，单位 mg/m³ |
| `temperature` | 数字 | 温度，单位 ℃ |
| `humidity` | 数字 | 湿度，单位 % |
| `ssid` | string | 设备连接的热点名 |
| `version` | string | 固件版本 |
| `brightness` | int | 屏幕亮度：`0` 关屏，`1`–`4` 亮度档 |
| `interval` | int | 传感器上报周期，秒，范围 1–255 |
| `zone` | int | 时区，单位为分钟，范围 -720–840（中国为 `480`） |
| `time` | int | 手动校时：请求时写 `-1`，设备回报校时结果时间戳 |
| `cmd` | string | 指令，目前仅 `restart`（重启设备） |
| `ota_progress` | int | 固件升级进度：`0`–`99` 进行中，`≥100` 成功，`-1` 失败 |
| `setting` | object | 批量设置，见下 |
| `task_0` … `task_4` | object | 5 组定时任务，见下 |

### `setting` 子对象

| 字段 | 说明 |
| --- | --- |
| `name` | 设置设备名称（最长 32 字节） |
| `ota` | 设置固件下载地址（以 `http` 开头的 URL），设备自行下载升级 |
| `mqtt_uri` / `mqtt_port` / `mqtt_user` / `mqtt_password` | 设置设备要连接的 MQTT 服务器 |

> 说明：设备**不会**回报自己当前保存的 MQTT 服务器配置，只能下发。

## 5. 定时任务

设备内置 5 组定时任务，按「时:分」触发一个屏幕亮度动作；任务存在设备里，服务器离线也会执行。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `hour` | int | 0–23 |
| `minute` | int | 0–59 |
| `brightness` | int | 触发动作：`0` 关屏，`1`–`4` 亮度档 |
| `on` | int | 是否启用：`1` 启用，`0` 停用 |

- 查询全部任务：`{"mac":"…","task_0":{},"task_1":{},"task_2":{},"task_3":{},"task_4":{}}`
- 设置某一组：`{"mac":"…","task_0":{"hour":8,"minute":30,"brightness":4,"on":1}}`（四个字段必须齐全）
- 第 5 组 `task_4` 通常被「倒计时」占用：倒计时 = 写入一组「当前时间 + N 小时 M 分」的一次性任务。

## 6. 设备发现（局域网）

服务端周期性向 `255.255.255.255:10182` 广播：

```json
{ "cmd": "device report" }
```

局域网内的设备会以如下结构回应（同时回给广播地址与请求方地址，端口 `10181`）：

```json
{ "name": "zM1_1234", "mac": "aabbccddeeff", "type": 4 }
```

`type` 为设备类型编号，zM1 固定为 `4`。部分固件还会通过 mDNS 广播 `_zcontrol._tcp`，
本工具把 mDNS 作为补充发现手段（广播探测为主）。

## 7. MQTT 配置同步

设备首次联网后需要知道 broker 地址，由服务端/客户端通过 **UDP 广播**（此时设备还没连上 broker）下发：

```json
{
  "name": "zM1_1234",
  "mac": "aabbccddeeff",
  "setting": { "mqtt_uri": "192.168.1.10", "mqtt_port": 1883, "mqtt_user": "user", "mqtt_password": "pass" }
}
```

`mqtt_uri` 只带主机名，端口单独放在 `mqtt_port`。设备收到后会以同样结构回显一条报文，
可用于确认配置是否生效。清空配置（`mqtt_uri` 为空字符串、`mqtt_port` 为 `0`）会让设备断开 broker，
本工具在这种情况下会先要求二次确认。

## 8. 固件升级

1. 客户端把固件下载地址写进设备：`{"mac":"…","setting":{"ota":"https://…/ota.bin"}}`
2. 设备自行下载并升级，过程中周期回报 `ota_progress`；升级期间不要断电。

版本检查由服务端完成（读取固件发布源的版本信息与固件地址），再把地址下发给设备。

## 9. 实机观测到的一些细节

- 数值字段常常以**字符串**形式上报（例如 `"temperature":"23.5"`），需要容错解析。
- 校时回报的时间戳**已叠加时区偏移**（`zone=480` 时约为 UTC+8 小时），
  即「设备本地时间对应的 UNIX 时间戳」。
- 无 MQTT 通道时（纯 UDP）收不到 `availability`，在线状态只能靠 MQTT 判断。
- 未获取到某组定时任务时设备可能不返回该字段，界面应显示占位而不是默认值。
